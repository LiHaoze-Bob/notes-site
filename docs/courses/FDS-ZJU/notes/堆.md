- 堆（heap）也称作优先队列（priority queue），支持插入值、找最小/大值，删除最小/大值
- 二叉堆（binary heap）是一种完全二叉树，满足以下性质：
    - 任意节点的值都不大于（或不小于）其父节点的值（即最大堆或最小堆）

!!! note "为什么需要heap"
    对于`有序`和`无序`的数组和链表，`插入`和`删除`的时间复杂度不平衡，一个为$O(N)$和一个$O(1)$，但是堆都为$O(logN)$

 >我们只需要最值，而二叉堆不用指针，维护较少，本身平衡，优于AVL树，但是对于其他元素，为$O(N)$
- 最大堆和最小堆的逻辑是对称的
### Head {#head}
```c
#include <stdio.h>
#include <stdlib.h>
#include <limits.h>

typedef int ElementType;

// 定义优先级队列结构
struct HeapStruct {
    int Capacity;     // 最大容量
    int Size;         // 当前元素个数
    ElementType *Elements; // 存储数组
};

typedef struct HeapStruct *PriorityQueue;

// 哨兵位（MinData）设置在 Elements[0]，比所有可能输入都小
#define MinData -32767
```


!!! note "哨兵的作用"
    `BT[0]` is not used
       在 `Insert` 的 `for` 循环中，我们判断 `H->Elements[i/2] > X`。如果 `X` 是当前堆中最小的，它会一直上爬到索引 `1`。此时 `i/2` 为 `0`。因为 `Elements[0]` 是 `MinData`，循环条件必然失败，从而停止。这样**避免了每次循环都要判断 `i > 1`**。


### Initialize {#initialize}
```c
PriorityQueue Initialize(int MaxElements) {
    PriorityQueue H;

    H = malloc(sizeof(struct HeapStruct));
    // 数组大小为 MaxElements + 1 (0号位置留给哨兵)
    H->Elements = malloc((MaxElements + 1) * sizeof(ElementType));
    
    H->Capacity = MaxElements;
    H->Size = 0;
    H->Elements[0] = MinData; // 哨兵：防止插入时索引越界

    return H;
}
```

### Insert && Percolate Up {#insert-percolate-up}
```c
void Insert(ElementType X, PriorityQueue H) {
    int i;

    if (H->Size == H->Capacity) {
        printf("Priority queue is full\n");
        return;
    }

    // 1. i 指向新的末尾空位
    // 2. 将 X 与父节点 H->Elements[i/2] 比较
    // 3. 如果父节点比 X 大，就把父节点拉下来，i 指向上方
    for (i = ++H->Size; H->Elements[i / 2] > X; i /= 2) {
        H->Elements[i] = H->Elements[i / 2];
    }
    
    // 4. 找到合适位置，放入 X
    H->Elements[i] = X;
}
```
$T(N) = O(logN)$
### Delete Min && Percolate Down {#delete-min-percolate-down}
```c
ElementType DeleteMin(PriorityQueue H) {
    int i, Child;
    ElementType MinElement, LastElement;

    if (H->Size == 0) {
        printf("Priority queue is empty\n");
        return H->Elements[0];
    }

    MinElement = H->Elements[1];       // 取出根节点（最小值）
    LastElement = H->Elements[H->Size--]; // 拿到最后一个元素

    // 下滤过程 
    for (i = 1; i * 2 <= H->Size; i = Child) {
        // 找到更小的儿子
        Child = i * 2;
        if (Child != H->Size && H->Elements[Child + 1] < H->Elements[Child]) {
            Child++;
        }

        // 如果最后一个元素比儿子大，则把儿子往上提
        if (LastElement > H->Elements[Child]) {
            H->Elements[i] = H->Elements[Child];
        } else {
            break; // 找到了合适位置
        }
    }
    H->Elements[i] = LastElement;
    return MinElement;
}
```
$T(N) = O(logN)$

### BuildHeap {#buildheap}
```c
void BuildHeap(PriorityQueue H) {
    // 从最后一个非叶子节点 (Size/2) 开始
    // 直到根节点 (1)
    for (int i = H->Size / 2; i > 0; i--) {
        PercolateDown(i, H);
    }
}
```

!!! proof
    由于结点集中在底层，采用自底向上的的`PercolateDown`，$T(N) = O(N)$，优于$N$次的`insert`。


    $$S = \sum_{i=0}^{h} 2^{h-i} \cdot i$$




    $$S = 2^{h+1} - (h + 2)$$


    我们将 $N = 2^{h+1} - 1$ 代入结果：
    *   $S = N - (h + 1)$
    *   由于 $h = \log_2(N+1) - 1$，所以 $h$ 约等于 $\log N$。
    *   $S = N - \log N - 1$

    当 $N$ 趋于无穷大时，$S \approx N$。

### DecreaseKey {#decreasekey}
```c
void DecreaseKey(int P, ElementType Delta, PriorityQueue H) {
    H->Elements[P] -= Delta;
    
    // 因为值变小了，向上浮动 (类似 Insert 里的上滤)
    ElementType Temp = H->Elements[P];
    int i;
    for (i = P; H->Elements[i / 2] > Temp; i /= 2) {
        H->Elements[i] = H->Elements[i / 2];
    }
    H->Elements[i] = Temp;
}
```

### IncreaseKey {#increasekey}
```c
void IncreaseKey(int P, ElementType Delta, PriorityQueue H) {
    H->Elements[P] += Delta;
    
    // 因为值变大了，向下沉入 (类似 DeleteMin 里的下滤)
    // 这里调用之前写好的 PercolateDown(P, H) 即可
    PercolateDown(P, H); 
}
```

### Delete {#delete}
```c
void Delete(int P, PriorityQueue H) {
    // 将其减小到最小，使其升至根部
    DecreaseKey(P, INF, H); 
    // 弹出根部
    DeleteMin(H);
}
```


!!! lemma

    设 $i$ 为当前节点索引，$n$ 为堆中节点总数。



    $$
    \text{index of parent}(i) = 
    \begin{cases} 
    \lfloor i/2 \rfloor & \text{if } i \neq 1 \\ 
    \text{None} & \text{if } i = 1 
    \end{cases}
    $$





    $$
    \text{index of left\_child}(i) = 
    \begin{cases} 
    2i & \text{if } 2i \leq n \\ 
    \text{None} & \text{if } 2i > n 
    \end{cases}
    $$






    $$
    \text{index of right\_child}(i) = 
    \begin{cases} 
    2i + 1 & \text{if } 2i + 1 \leq n \\ 
    \text{None} & \text{if } 2i + 1 > n 
    \end{cases}
    $$





### TopK Problem {#topk-problem}
```c
void TopK(ElementType Dataset[], int N, int K) {
    // 1. 创建一个大小为 K 的最小堆
    PriorityQueue H = Initialize(K);

    // 2. 将前 K 个元素直接放入并转化为堆 (BuildHeap)
    for (int i = 0; i < K; i++) {
        H->Elements[i + 1] = Dataset[i];
    }
    H->Size = K;
    BuildHeap(H); // 使得这 K 个数满足最小堆性质

    // 3. 遍历剩下的元素
    for (int i = K; i < N; i++) {
        // 如果当前数比“守门员”（堆顶）大
        if (Dataset[i] > H->Elements[1]) {
            H->Elements[1] = Dataset[i]; // 替换守门员
            PercolateDown(1, H);         // 重新调整堆
        }
    }

    // 4. 现在 H->Elements[1...K] 就是最大的 K 个数
    for (int i = 1; i <= K; i++) {
        printf("%d ", H->Elements[i]);
    }
}
```


$$T(N) = O(NlogK)$$



$$S(N) = O(K)$$



### d-Heaps {#d-heaps}
*   **索引计算**（假设从 1 开始存储）：
    *   节点 $i$ 的孩子节点范围：从 $d(i-1) + 2$ 到 $di + 1$
    *   节点 $i$ 的父节点索引：$\lfloor (i + d - 2) / d \rfloor$
    通过前面的结点认领了几个孩子来计算

Insert —— 变快：$O(\log_d N)$。
DeleteMin —— 变慢：$O(d \times \log_d N)$。
#### ① 复杂度 $O(d \log_d N)$ {#1-复杂度-od-log_d-n}
这是 `DeleteMin` 的瓶颈。当 $d$ 很大时，$d$ 项的增长速度远快于 $\log_d N$ 的下降速度。

#### ② 位移 (Bit Shift)  {#2-位移-bit-shift}
*   在二叉堆 ($d=2$) 中，计算父子索引只需要左移 (`<<1`) 或右移 (`>>1`)，这是 CPU 处理最快的指令。
*   如果 $d$ 不是 2 的幂（例如 $d=3$），计算索引需要进行真正的整数乘除法，这在底层硬件上比位移慢得多，所以通常会选择 $d$ 为 2 的幂

#### ③ 外部存储  {#3-外部存储}
当堆的数据量巨大，无法全部装入内存（RAM），必须存放在磁盘上时。磁盘 IO（读取）非常慢，而内存中的计算（比较 $d$ 个孩子）相对很快。我们希望尽可能减少读取磁盘的次数。由于 $d$-堆非常矮，访问一个路径涉及的节点（磁盘块）极少。这和数据库索引使用 **B-树**（多路平衡搜索树）的逻辑是一模一样的。
